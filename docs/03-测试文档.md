## T1 测试环境与数据准备

1. 环境：MySQL 8 + Redis 7 + MongoDB 6 本机（或 Docker），后端 `dev` profile、前端 `yarn dev`，Nginx 可选（仅代理相关用例需要）。
2. 账号（4.5 初始化）：`student01~03`、`repairer01~03`、`manager01/02`；密码均为初始化脚本中的 BCrypt 明文（默认 `123456`，仅测试环境）。
3. 楼栋数据：`manager01` 关联 A1/A2，`manager02` 关联 B1（用于 TC-M-05 越权用例，依赖 `t_manager_building`）。
4. 数据清理：每轮用例前 `TRUNCATE` 业务表并重跑 `init_data.sql`；Redis 清 `sr:order:*`、`sr:auth:*`；MongoDB 清 `order_track`、`operation_log`、`fs.*`。
5. 时间相关用例（超时、自动确认、自动关闭）**不要真等**：手动触发 `OrderTimeoutJob` / `OrderAutoCloseJob`，或临时把 cron 改为每分钟，执行后立即恢复。

### 13.7 数据一致性验证（每个并发/状态用例后必须执行）

```sql
-- 1. 同一工单是否被重复抢单（并发超卖）——仅在"无管理员释放"的并发用例后执行
--    注意：release 后重新入池再被抢属正常业务，会产生第 2 条 GRAB，不能直接判为超卖
SELECT order_id, COUNT(1) c FROM t_dispatch_record
 WHERE dispatch_type = 'GRAB' AND deleted = 0
 GROUP BY order_id HAVING c > 1;

-- 1b. 工单当前 assignee 是否与"最近一次有效派单/抢单记录"一致
--     （防止"一单多派"后状态与派单记录脱节；拒单/释放已清空 assignee 的工单不在结果内）
SELECT o.id, o.status, o.assignee_id, d.assignee_id AS last_assignee
  FROM t_work_order o
  JOIN t_dispatch_record d ON d.id = (
       SELECT d2.id FROM t_dispatch_record d2
        WHERE d2.order_id = o.id AND d2.dispatch_type IN ('ASSIGN','GRAB') AND d2.deleted = 0
        ORDER BY d2.id DESC LIMIT 1)
 WHERE o.status IN ('ASSIGNED','ACCEPTED','ARRIVED')
   AND (o.assignee_id IS NULL OR o.assignee_id <> d.assignee_id);

-- 2. 状态与时间字段是否自洽
SELECT id, status, accept_time, arrive_time, finish_time FROM t_work_order
 WHERE (status IN ('ACCEPTED','ARRIVED','FINISHED','CONFIRMED','CLOSED') AND accept_time IS NULL)
    OR (status IN ('ARRIVED','FINISHED','CONFIRMED','CLOSED') AND arrive_time IS NULL)
    OR (status IN ('FINISHED','CONFIRMED','CLOSED') AND finish_time IS NULL);

-- 3. 已完工工单是否都有完工照片
SELECT o.id FROM t_work_order o
  LEFT JOIN t_order_image i ON i.order_id = o.id AND i.img_type = 'AFTER'
 WHERE o.status IN ('FINISHED','CONFIRMED','CLOSED') AND i.id IS NULL;

-- 4. 是否一单多评
SELECT order_id, COUNT(1) c FROM t_evaluation GROUP BY order_id HAVING c > 1;
```

以上 SQL 均须返回 **0 行**（SQL#1 只在未发生 `RELEASE` 的并发抢单用例后执行；发生 `RELEASE` 后重抢的工单请改用 SQL#1b 校验）。
