**路由守卫（`router/guards.js`）**

1. 无 token → 除 `/login` 外全部重定向 `/login?redirect=原路径`。
2. 有 token 但角色不匹配前缀（如学生访问 `/admin/*`）→ `/`（并 Toast"无权限访问"）。
3. 已登录访问 `/login` → 直接跳首页 `/`。
4. 路由级 `meta: { title, roles: [] }`，菜单（`layout/menus.js`）与守卫共用同一份 roles，避免"菜单能点、接口 403"。

## F4 请求封装与错误处理（`src/api/request.js`）

```javascript
const service = axios.create({ baseURL: '/api/v1', timeout: 15000 })

// 请求拦截：注入 token（sessionStorage：每标签独立登录态）
service.interceptors.request.use(cfg => {
  const token = sessionStorage.getItem('token')
  if (token) cfg.headers.Authorization = `Bearer ${token}`
  return cfg
})

// 响应拦截：统一拆包 + 分类处理
service.interceptors.response.use(
  res => {
    const { code, message, data } = res.data
    if (code === 200) return data
    handleBizError(code, message)              // 见下表，非阻塞 Toast
    return Promise.reject(Object.assign(new Error(message), { code }))
  },
  err => {
    const status = err.response?.status
    const body = err.response?.data || {}
    if (status === 401) { clearAuth(); router.replace('/login') }
    else if (status === 403) ElMessage.error(body.message || '无权限操作')
    else if (status === 503) ElMessage.error(body.message || '图片服务暂不可用，请稍后再试')
    else if (status === 429) ElMessage.warning(body.message || '操作过于频繁，请稍后再试')
    else if (status >= 500) ElMessage.error(body.message || '服务异常，请稍后再试')
    else ElMessage.error(body.message || '网络异常')
    return Promise.reject(err)
  }
)
```

| 场景 | 前端行为 |
| --- | --- |
| `401` / 业务码 401 | 清 token、断开 WS、跳登录，保留 `redirect` |
| `403` / 40301 | Toast 原样展示后端 `message`，不跳转 |
| `40009 STATUS_NOT_ALLOWED` | Toast 后**强制刷新详情**（说明本地状态已过期） |
| `40902 ALREADY_EVALUATED` | Toast"该工单已评价"，刷新详情 |
| `40904 CONCURRENT_MODIFIED` | Toast 后刷新详情与列表（并发修改，本地数据已过期） |
| `40905 ALREADY_MARKED_TIMEOUT` | 幂等成功：不报错，直接刷新超时列表 |
| `40901 ORDER_ALREADY_TAKEN` | Toast"手慢了，该工单已被抢"，并把该行从抢单池移除 |
| `40903 DUPLICATE_SUBMIT` | Toast"请勿重复提交"，保留表单内容 |
| `40005 / 40006` 上传类 | 在 `ImageUploader` 内就地提示，不弹窗 |
| `503 FILE_SERVICE_UNAVAILABLE` | 上传按钮置灰 30 秒 + 提示"图片服务暂不可用" |

> 所有错误提示统一走 `ElMessage`（非阻塞）；只有"删除/释放工单/取消报修"等不可逆操作才用 `ElMessageBox.confirm` 做二次确认。

## F5 图片上传规范（`components/business/ImageUploader.vue` + `composables/useUpload.js`）

- 接口：`POST /api/v1/files/upload`，`multipart/form-data`，字段 `file` + `bizType`（`BEFORE` / `AFTER` / `AVATAR` / `CAROUSEL`），**一次只传 1 张**，成功返回 `{ fileId, url }`。
- 校验：类型 `jpg/jpeg/png/webp`；大小 ≤ 5MB；`BEFORE`、`AFTER` 各自 ≤ 6 张，单工单合计 ≤ 12 张（BR-13）——前端先拦，服务端仍会再校验一次。
- 交互：选择即上传、逐张进度条、失败可重试、可删除、可点击预览（`el-image` 预览）；上传中禁用提交按钮。
- 提交：报修/完工只提交 `fileIds` 数组，不提交 base64，不提交 URL。
- 头像：`bizType=AVATAR` 上传成功后取返回的 `url`，调用 `PUT /api/v1/users/profile` 提交 `{ "avatar": url }`，服务端回写 `t_user.avatar`（不写 `t_order_image`）。
- 首页轮播：`bizType=CAROUSEL` 上传成功后，把 `fileId` 与 `url` 一起 `POST /manager/carousels`；建议 16:6 横图、单张 ≤ 5MB、1~8 张。
- 列表项必须是响应式对象：`useUpload` 中先 `reactive({ fileId, url, status, raw, uid })` 再 `push` 进数组；若 `push` 普通对象后直接改 `status/url`，会绕过 Proxy 的 set 拦截，导致上传成功但视图一直停在“上传中”。

## F6 WebSocket 实时通知（`utils/websocket.js` + `stores/notice.js`）

```javascript
const url = `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws/notice?token=${token}`

// 心跳 30s；断线按指数退避重连（1s→2s→4s→最长 30s）；重连失败降级为 30s 轮询未读数
ws.onmessage = e => {
  const msg = JSON.parse(e.data)
  if (msg.type === 'pong') return
  noticeStore.onPush(msg)              // 站内信列表 + 未读角标 + ElNotification
}
```

- 触发通知的事件：`ORDER_ASSIGNED`（派单/抢单）、`ORDER_ACCEPTED`、`ORDER_ARRIVED`、`ORDER_REJECTED`、`ORDER_FINISHED`、`ORDER_EVALUATED`、`ORDER_REWORK`、`ORDER_TIMEOUT`、`ORDER_URGED`（共 9 种，与《后端开发文档》8.5 及 `NoticeTypeEnum` 一致）。
- 只做"提示与角标"，**不直接改业务状态**；收到 `ORDER_*` 后对当前详情页调一次详情接口刷新。
- 页面隐藏（`document.hidden`）时仍接收消息，但不弹 `ElNotification`，只累加未读。
- 登出/401：主动 `ws.close()` 并清除重连定时器，防止重连风暴。

## F7 交互与展示规范

1. **三要素**：每次请求 = loading（按钮 loading 或骨架屏）→ 结果 → Toast。
2. 列表页：筛选条件写入 URL query（刷新/回退不丢）；分页默认 10 条；空态用 `EmptyState.vue`。
3. 时间：统一 `YYYY-MM-DD HH:mm`；时长展示为 `Xh Ym`；百分比后端返回 0~1 的小数（3 位），前端按 1 位小数百分比展示。
4. 状态：`OrderStatusTag.vue` 统一色板（CREATED 灰、ASSIGNED 蓝、ACCEPTED 青、ARRIVED 橙、FINISHED 紫、REWORKING 橙红、CONFIRMED 绿、CLOSED 深绿、CANCELLED 浅灰）。
5. 超时：`timeout_flag=1` 时行首加红色标记与 `timeout_type` 文案（ACCEPT/ARRIVE/FINISH）。
6. 优先级：仅管理员可见 `PrioritySelect`；学生端**不展示优先级选择**（BR-17），列表只显示只读标签。
7. 统计页：默认区间"近 30 天"（对应 10.2 `[近30天 00:00, 次日 00:00)`），指标卡 + 三个图表（类型分布、平均时长、返修率），切区间必须重新请求，不前端算。
8. 返修：学生点「反馈未修好」弹出必填原因输入框（可补图），提交后停留在原工单并进入「返修中」；详情页「维修轮次」表与时间轴按「第 N 轮」展示，返回 `rounds/acceptances` 由后端详情接口提供。

```javascript
import fs from 'node:fs'
import { fileURLToPath } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import Components from 'unplugin-vue-components/vite'

const kebab = (name) =>
  name
    .replace(/([a-z0-9])([A-Z])/g, '$1-$2')
    .replace(/([A-Z])([A-Z][a-z])/g, '$1-$2')
    .toLowerCase()

// 没有独立 js 入口的子组件，必须映射到父组件目录
const SUB_COMPONENTS = {
  'checkbox-group': 'checkbox',
  'checkbox-button': 'checkbox',
  'form-item': 'form',
  option: 'select',
  'option-group': 'select',
  'table-column': 'table',
  'radio-group': 'radio',
  'radio-button': 'radio'
}

const componentEntry = (partial) =>
  fileURLToPath(
    new URL(`./node_modules/element-plus/es/components/${partial}/index.mjs`, import.meta.url)
  )

/**
 * Element Plus 按需引入解析器。
 * 官方 ElementPlusResolver 从 element-plus/es 桶文件导入、依赖 tree-shaking，
 * 实测会把整包打进产物；这里直接指向具体组件目录（含样式副作用导入）。
 */
function elementPlusResolver() {
  return (name) => {
    if (!/^El[A-Z]/.test(name)) return undefined
    const partial = kebab(name.slice(2))
    const folder = fs.existsSync(componentEntry(partial)) ? partial : SUB_COMPONENTS[partial]
    if (!folder) return undefined
    return {
      name,
      from: `element-plus/es/components/${folder}/index`,
      // 必须引「样式入口」而非单个 theme-chalk 文件：样式入口会连带依赖组件样式
      //（如 select 依赖 scrollbar / popper / tag），只引单文件会出现定位错乱、下拉框闪烁
      sideEffects: [
        'element-plus/es/components/base/style/css',
        // 子组件（如 ElOption → partial=option）没有独立 style 目录，必须用 folder（select）
        `element-plus/es/components/${folder}/style/css`
      ]
    }
  }
}

export default defineConfig({
  plugins: [
    vue(),
    Components({ resolvers: [elementPlusResolver()], dts: false })
  ],
  resolve: {
    // 用 fileURLToPath 解析绝对路径，Windows 下同样可用（写 '/src' 在部分场景会被当成盘根）
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) }
  },
  server: {
    port: 5173,
    strictPort: true,          // 5173 被占直接报错，不静默换端口（否则后端代理配错很难发现）
    proxy: {
      // 后端接口本身以 /api 开头，无需 rewrite
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      },
      // WebSocket 通知：target 用 http + ws:true，Vite 会自动升级协议
      '/ws': {
        target: 'http://localhost:8080',
        ws: true,
        changeOrigin: true
      }
    }
  },
  build: {
    outDir: 'dist',
    chunkSizeWarningLimit: 900,
    sourcemap: false,
    rollupOptions: {
      output: {
        // 大依赖拆包，便于浏览器缓存（Element Plus / ECharts 变动少）
        manualChunks(id) {
          if (!id.includes('node_modules')) return undefined
          if (id.includes('echarts') || id.includes('zrender')) return 'echarts'
          if (id.includes('element-plus') || id.includes('@element-plus')) return 'element-plus'
          return 'vendor'
        }
      }
    }
  }
})
```

**`frontend/src/api/request.js`（axios 实例：同源 + token + 401/403 分流）**

> 完整实现**只在 F4 维护一份**（含业务码分流、401 跳登录带 `redirect`、403/429/503/5xx 分类 Toast），此处不再重复，避免两份代码不一致。落地约定：
>
> - `baseURL = '/api/v1'`，`timeout = 15000`；开发走 Vite `proxy`、生产走 Nginx 反代，均为同源，无需 CORS 与绝对地址。
> - token 存 `sessionStorage`（key `token`，按标签页隔离），请求头 `Authorization: Bearer {token}`。
> - 响应体 `{ code, message, data }`：`code=200` 直接返回 `data`；`401`/HTTP 401 清登录态并跳 `/login?redirect=原路径`；其余按 F4 错误码表给非阻塞 Toast。

> **字段名必须与后端对齐**：本文档 8.1 约定响应体是 `{ code, message, data }`，所以 F4 的响应拦截里读 `body.message`。若参照项目用的是 `msg`，两处必须统一成一个，否则错误提示永远显示"请求失败"。这也是 13.9 静态核对第 4 项的检查内容之一。
>
> **token 清理策略**：登录成功后写入 `sessionStorage.token`（key 为 `token`）；退出登录时**先调** **`POST /auth/logout`**（让 Redis 里的 token 失效，实现"强制下线"）再清除本地 token，否则旧 token 在 2 小时有效期内仍可被使用。
>
> **多账号说明**：`sessionStorage` 按标签页隔离，因此同一浏览器可开多个标签分别登录不同账号，互不覆盖；关闭标签即退出该标签登录，新开标签需重新登录。后端仍是**按账号单端登录**（`sr:auth:token:{userId}` 唯一），同一账号在两个标签/设备登录仍会互踢。

### 15.4 错误码表（`ResultCode`）
